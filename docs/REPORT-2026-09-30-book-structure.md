## 책 구조(표지·속지·책등) 확정 결과

커밋 2개: e37ac3a(시점 확인 도구), 6a21434(책 구조). push는 하지 않았습니다.

모든 비교는 에뮬레이터 릴리스 빌드, 같은 18권 배치, 같은 화면 폭에서 했습니다. tsc 오류는 없고 테스트 190개가 모두 통과합니다(구조 테스트 2개 추가).

그대로 둔 것:
- 책 치수·배치·충돌·접촉·저장 상태·조작
- 글자 크기·줄바꿈·굵기
- 선반 간격 비교안과 그림자 세기

### 1. 시점: 실제 원인은 저장된 보기 각 8°
- 지난번 첨부 화면이 넓게 보인 것은 카메라 오류가 아니었습니다. 제 8° 확인 스크립트가 꾸미기에서 시점을 8°로 끈 채 끝났고, 보기 각은 사용자 설정으로 저장되는 값이라 앱을 다시 켰을 때 8°로 열렸습니다.
  - 선반 판 높이가 3°에서는 52px, 첨부 화면은 85px로, 8° 캡처(85px)와 같았습니다.
- 실제 렌더 프레임 값을 화면에 적어 확인했습니다(측정 번들 `?cam=1`).
  - 3°: 저장 3°, 적용 3.00°, ky 0.0524(tan 3°), kx 0.035, 배율 1.0549dp/DU(2.769px/DU), 줄 높이 기준 ky 0.0524
  - 8°: 저장 8°, 적용 8.00°, ky 0.1405(tan 8°), 줄 높이 기준 ky 0.1405
  - 꾸미기 중에는 줄 높이만 8° 기준으로 재는 원래 규칙 그대로입니다.
- 중복 확인:
  - 책과 선반은 같은 카메라 공유 값을 씁니다.
  - 수정 전후 같은 각에서 선반 판 위치와 책머리 위쪽 끝이 픽셀 단위로 같습니다(3° 판 915~967, 데미안 위 끝 440 / 8° 878~963, 403).
  - 그래서 색 때문에 커 보인 것이 아니라, 3° → 8°로 노출 면적 자체가 바뀐 것입니다.
- 3°/8° 규칙은 원래대로였으므로 각도는 고치지 않았습니다. 에뮬레이터는 3°로 되돌려 두었습니다.
- 67번: 전후 3°/8° 전체 화면과 적용값 표시.

### 2. 표지·속지·책등 구조
원인: 머리·꼬리·배쪽 면은 면 전체를 판 색으로 칠하고, 그 안에 화면 좌표로 줄인 사각형 하나를 종이로 얹는 구조였습니다.
- 판·책등·배쪽이 구분되지 않았습니다.
- 종이 사각형 네 변 모두에 그늘 선이 있었습니다. 그래서 속이 빈 상자 안쪽처럼 보였습니다. 데미안의 갈피 주변 흰 테두리 상자와 밝은 밤의 흰 뚜껑이 이것 때문이었습니다.
- 둥근 면 윤곽과 종이 칸이 맞지 않아, 뒤쪽 끝에 판 색 띠가 남았습니다.

고친 내용: 구조를 책 좌표(두께 x·높이 y·깊이 z, 책등 z=0·배쪽 z=W)에서 정하고 지금 자세 그대로 투영합니다. 세우기·표지 전시·눕히기·돌리기 뒤에도 같은 면에 붙어 따라갑니다.
- 앞·뒤표지: 두께 양끝의 얇은 판 두 장입니다(두께의 8%, 1.1~1.8DU).
  - 판 윗모서리에 책색을 밝힌 가는 밝음을 넣었습니다. 빛을 등진 면에서는 약하게 합니다.
  - 판 안쪽 면이 종이와 만나는 곳에 책색을 낮춘 좁은 그늘을 넣어, 판 두께가 읽힙니다.
- 책등 띠: 머리·꼬리에서 제본된 쪽에 둡니다.
- 속지: 판 사이의 밝은 종이 묶음으로, 종이색 #FAF8F2는 그대로입니다.
  - 그늘은 판·책등과 맞닿는 쪽에만 폭에 비례해 부드럽게 넣고, 열린 배쪽에는 넣지 않았습니다.
  - 종이 결은 낱장이 표지와 나란하므로, 머리에서는 책등→배쪽 방향, 배쪽 면에서는 세로 방향입니다.
- 배쪽: 판이 종이보다 1.6DU 튀어나온 틈을 조금 어두운 종이 끝으로 그립니다.
- 갈피: 종이 사이로 들어가는 자리에 좁은 틈 그늘을 넣었습니다.
- 가운데 검은 줄이나 두꺼운 테두리는 쓰지 않았습니다.
- 3°~8°에서는 깊이 방향이 ky배로 눌려서, 머리 면의 배쪽 틈이나 책등 띠는 0.2DU 정도라 거의 안 보입니다. 이 각도에서는 두께 방향의 판 두 장·속지·판 순서로 구조가 읽힙니다. 책등이 정면일 때 배쪽이 안 보이는 것은 그대로 두었습니다.
- 면 구분 확인색(측정 모드 `?sh=faces`, 일반 화면에는 없음)으로 배치가 맞는지 확인했습니다(69번).
  - 책등 파랑, 앞표지 빨강, 판 면 초록 윤곽, 속지 노랑, 배쪽 틈 보라, 안쪽 그늘 주황, 판 윗모서리 흰, 판 안쪽 검정

### 3. 곡면과 하이라이트
- 책등 원통 명암의 밝음이 폭의 약 1/3에 넓게 퍼져 있었습니다. 이를 광원을 가장 정면으로 받는 좁은 곡면에만 두도록 좁혔습니다. 가운데는 책색 중간색이고, 옆면으로 넘어가는 반대쪽은 완만한 그늘입니다.
- 머리 쪽 둥근 띠의 밝음을 0.45 → 0.3으로 낮췄습니다(밝음이 머리에 몰리던 것 완화).
- 모든 명암은 공통 광원과 책 회전으로 매 프레임 계산합니다. 화면 왼쪽에 고정된 흰 선이 아닙니다.
- 텍스처 중복 확인:
  - 붓결과 책등 장면 그림에는 굽힌 명암이 없었습니다.
  - 표지 그림 왼쪽(제본 쪽) 끝 약 1%에 시안에서 뽑을 때 따라온 어두운 윤곽이 있었습니다(b04 50 vs 안쪽 82, b07 71 vs 102). 코드의 제본 홈과 겹치므로 그 줄이 면 밖으로 가게 1.5% 잘랐습니다.

### 직접 확인한 것
- 3°/8° 정착 화면의 실제 적용값, 선반·책머리 노출 전후
- 대표 세 권(데미안, 크림색 눕힌 책, 분홍 표지)과 밝은 밤의 머리·끝면 구조
- 면 구분 확인색으로 본 면 배치
- 월든 책등 ↔ 표지 회전의 중간 프레임(느리게 모드): 책등과 표지가 이어지고 머리 띠도 끊기지 않았습니다.
- 흰 기대기 왼쪽 ↔ 바로: 명암이 책을 따라 돕니다.
- 8° 자세 변경, 선택·끌기·놓기 후 제자리
- 구조 단위 테스트: 세운 책과 눕힌 책에서 판·속지 순서와 종이 결 방향이 책을 따라 돕니다.

### 확인하지 못한 것
- 기울이기 손잡이 조작: 월든은 양옆 책과 벽 때문에 돌리거나 젖힐 자리가 없어서, 손잡이를 끌어도 각도가 바뀌지 않았습니다(조작 규칙상 자리가 없으면 원래대로). 여유 공간이 있는 책으로 다시 봐야 합니다.
- 눕힘으로 바꾸는 전환: 해당 선반에 눕힐 자리가 없어 적용되지 않았습니다. 이미 누워 있는 더미는 3°·8° 정지 화면으로만 봤습니다.
- 기대기와 표지로 바꾸는 전환의 중간 프레임: 느리게 모드가 자세 전환 경로에만 걸려서 이 둘은 거의 바로 끝났습니다. 에뮬레이터 화면 녹화는 약 1.5프레임/초만 잡혀서 영상에도 중간 모습이 거의 없습니다.
- 끄는 중인 책 자체가 캡처에 보이지 않았습니다. 이번 수정 전 캡처(g6b)도 같아서 이번 변경 때문은 아닌 것으로 보지만, 원인은 따로 확인하지 않았습니다.
- 실기기 화면과 성능: 이번 빌드의 프레임 시간은 재지 않았습니다.
  - 확인 중 에뮬레이터가 메모리 부족(여유 250MB, 스왑 880MB)으로 시스템과 앱 '응답 없음'이 한 번 떴습니다.
  - 에뮬레이터를 재부팅한 뒤에는 같은 조작에서 다시 나지 않았습니다.
- 선반 간격 비교안과 그림자 세기는 이번에 판단하지 않고 기준을 유지했습니다.
