## 3. 화면 확인에서 찾아 고친 것

- 키보드가 열리면 아래 고정 저장 버튼과 아래쪽 입력칸이 가려졌다(안드로이드 화면 끝까지 그리는 창은 키보드가 열려도 줄지 않는다). 공통 `Screen`이 안드로이드에서도 키보드 높이만큼 비키게 했다 → 갈피 남기기·수정, 책 정보 수정에서 저장 버튼이 키보드 위에 보이는 것 확인.
- 안드로이드 기본 스위치는 손잡이가 바탕 밖으로 커서 시안과 달랐다 → 시안 모양 스위치를 직접 그림(접근성 역할 switch·켜짐 상태 포함).
- 큰 글자에서 설정 설명 글이 스위치에 붙었다 → 목록 줄 글자와 오른쪽 요소 사이 간격.
- 작은 화면 + 큰 글자에서 좁은 '한 줄 메모' 칸의 입력 안내가 두 줄로 접히며 잘렸다 → 칸 아래 도움말로 옮김. 독서 끝의 쪽수 칸은 넓힘.
- 첫 구역이 제목에 너무 붙었다 → 시안처럼 간격을 넓힘.

## 4. 검증

- `npx tsc --noEmit` 통과. `npx jest` 43개 파일 474개 통과(공통 기준 시험 12개 추가). 린트는 프로젝트에 설정(eslint.config)이 없어 돌리지 않았다.
- 에뮬레이터(medium_phone 1080×2400, Expo Go, 개발 모드 번들)에서 위 화면을 열고 찍었다. 작은 화면은 `wm size 720x1280`·`wm density 320`(360×640dp)에 글자 크기 1.3배로 설정·갈피 남기기(키보드 포함)를 확인했다. 큰 글자 1.3배는 기본 크기에서도 설정을 확인했다.
- 긴 글: 검색 결과의 긴 저자 목록('George Orwell, G Orwell, George Orwel, …')이 잘리지 않고 3줄로 줄바꿈되는 것을 확인했다. 아주 긴 한국어 책 제목을 목록·상세에서 따로 넣어 보지는 않았다(목록 제목은 2줄까지, 머리줄 제목은 1줄로 줄임표).
- 빈 화면은 결과 없음·필터 결과 없음 문구를 공통 `Empty`로 바꿨지만, 갈피 0개·책 0권 같은 완전히 빈 데이터 화면은 실제 데이터를 지우지 않으려고 화면으로 확인하지 않았다.
- 화면 확인 중 실제 데이터를 바꾸지 않았다: 독서 타이머는 돌린 뒤 '버리기'로 저장하지 않았고, 수정 화면은 저장하지 않고 나왔다. 책은 추가하지 않았다.

## 5. 남은 예외·미완료

- 운영체제 확인창(Alert: 삭제·복원·버리기 등)은 그대로 둔다(지시: 운영체제 기본 화면을 억지로 재현하지 않음).
- 한국어 문장이 낱말 중간에서 줄바꿈된다(예: '동기/화는'). 바꾸기 전에도 같았던 안드로이드 기본 줄바꿈이다. 갈피 카드에는 이미 낱말 단위 줄바꿈(WordWrap)이 있으나 일반 화면 글자에는 넣지 않았다.
- 홈에서는 탭 바가 투명해 아래 줄 책 위에 탭 글자가 겹쳐 보일 수 있다(기존 설계, 바꾸지 않음).
- 개발용 화면(`dev-bookmark`, `dev-rebinding`)과 쓰이지 않는 옛 부품(`features/home/BookDetail.tsx`, `ui/Placeholder.tsx`)은 손대지 않았다.
- 개발 모드에서 코드를 고쳐 화면이 다시 불러와진 직후에는 책 표지(Skia 캔버스)가 빈 상자로 그려지는 일이 있었다. 앱을 새로 띄우면 정상이고, 이번 작업은 책 그리는 코드를 건드리지 않았다. 배포 번들에서는 확인하지 않았다.
- 실기기, iOS, 배포 모드 번들에서는 확인하지 못했다.

같이 고친 것
- 화면 바탕의 종이 결(PaperSurface)을 뺐다: 공통 화면 틀, 갈피 상세 바탕, 타이머 조작판. 갈피 카드의 종이·테이프·사진판, 빈 갈피 화면의 예시 종이는 그대로.
- 입력칸 위에 보조 글자가 오던 곳: 고르는 칸의 저자 줄·장정 편집 탭과 무늬 이름은 본문색, 사진 갈피의 점선 상자 바탕은 흰색.
- 화면 코드의 남은 고정 색: 갈피 넘김 점, 장정 체크 표시, 빈 책장 안내 바탕, 끌기 안내 바탕을 토큰 기준으로. 책 표지 대체색·타이머 장면·책장 손잡이는 그림이라 그대로.
- 아래 고정 버튼 위 구분선을 뺐다(시안에 없음).
- 검증: `tsc --noEmit` 통과, `jest` 43개 파일 479개 통과. 시험: 지정한 기준값, 바탕과 입력칸이 다른 토큰인지, 바탕류가 노란 크림·진한 베이지가 아닌지(빨강−파랑 차·밝기), 비활성·오류 구별, 대비.

비교: `docs/screenshots/2026-10-26-design/11-color.jpg`(시안 · 갈피 수정 · 설정 · 책 확인), `12-color-sweep.jpg`(책장 메뉴·책 상세·더 보기 시트·갈피 검색·읽기 목표 시트·서랍 빈 결과·통계·검색 결과). 꾸미기 패널도 확인했다.

시안과 다른 점(이번에는 색만 바꾸라는 요청이라 배치는 그대로 뒀다)
- 시안의 갈피 수정은 머리줄 아래에 연결된 책(‘느린 계절 · 한서윤’)을 보여 주고, 입력칸 이름이 굵으며 ‘선택’을 작은 회색 글자로 따로 단다. 쪽수 칸은 꽉 찬 폭에 ‘쪽’ 단위가 붙는다. 지금 앱은 ‘쪽수 (선택)’처럼 한 줄 이름, 쪽수 칸은 좁은 폭이다.
- 시안의 문장 입력칸 글자는 고딕으로 보인다. 앱은 갈피 문장을 명조(내용 글꼴)로 쓰는 기존 기준을 유지했다.

확인 못 한 것·남은 것
- 토스트(알림)는 선반을 추가·정리해야 떠서 실제 데이터를 바꾸지 않으려고 화면으로 확인하지 않았다(색은 본문색 바탕 + 흰 글자).
- 오류 상태(검색 오류 안내 상자·날짜 형식 오류)는 이번 색으로 화면 확인하지 않았다(토큰 대비 시험으로만 확인).
- 화면 확인 중 에뮬레이터가 adb 셸에 응답하지 않아 에뮬레이터를 껐다 다시 켰다(데이터는 그대로). 그 직전에 보내던 화면 크기 1080×1920 덮어쓰기는 적용되지 않았고, 지금은 기본 1080×2400이다.

## 8. 서랍·책 추가 시안, 갈피 종이 색, 하단 탭 바(같은 날 추가 요청)

## 9. 시안과 같은 글꼴·박스색(같은 날 추가 요청: "시안이랑 같은 글씨체랑 박스색으로 바꿔줘 전체")

글꼴 확인(`24-font-candidates.jpg`): 시안 글자(서랍·책 추가·갈피 수정)를 본고딕(Noto Sans KR)·Pretendard·나눔스퀘어라운드로 같은 높이에 그려 비교했다. 한글은 'ㅊ'·'ㅎ' 윗점이 가로획인 본고딕 뼈대(나눔스퀘어라운드는 세로 점), 영문·숫자는 Inter 모양('George'·'eighty' 폭과 g)이라 Pretendard와 같다. 굵은 글자는 Bold보다 한 단계 가벼운 SemiBold로 보인다.
- UI 글꼴을 Pretendard 1.3.9(SIL OFL 1.1) Regular·Medium·SemiBold로 바꿨다(`fonts.ui`·`uiMedium`·`uiBold`). 나눔스퀘어라운드 R은 지웠다(B·EB는 홈 머리글에만 남음).
- 같은 크기에서 Pretendard 한글 높이가 나눔스퀘어라운드보다 약 6.5% 작아(0.867 대 0.928em), 시안 글자 높이에 맞춰 제목 22·보조 설명 15로 다시 잡았다(나머지는 그대로 맞음).
- Pretendard 숫자는 폭이 달라 타이머·미니 타이머·요약 숫자에 tabular-nums(글꼴의 tnum)를 켰다.
- 갈피 작성·수정의 문장 입력칸도 시안처럼 Pretendard(갈피 카드에 보이는 문장은 명조 그대로).

박스색: 입력·검색칸은 이미 시안 박스 #F6F5F2였다. 흰 바탕에 테두리만 있던 박스를 시안 박스처럼 #F6F5F2 단색(테두리 없음)으로 채웠다: 보조·삭제 버튼, 칩, 장정 편집의 '그림 없음' 줄과 가·나·다 칩, 책 정보 상자의 사진 자리와 버튼 세 개, 책 추가·수정의 표지 자리(밝은 바탕이면 글자는 보조색).

비교: `21-font-fit.jpg`(시안과 같은 크기로 나란히: 서랍·책 추가·갈피 수정), `22-font-sweep-1.jpg`·`23-font-sweep-2.jpg`(설정·백업·책 확인·책 상세·정보 상자·갈피·갈피 수정·읽기·내 기록).
남은 차이: 서랍·책 추가 시안의 제목은 검정, 앱은 갈색(갈피 수정 시안 기준 유지). 홈 머리글('나의 책장'은 시안 글자 그림, 연도·완료는 나눔스퀘어라운드)은 책장 그림과 함께 맞춘 것이라 그대로 뒀다.

## 10. 홈 벽색을 화면 바탕과 맞춤(같은 날 추가 요청)

홈 책장 벽(`theme.ts`의 `bg`·`wall`)이 시안의 크림 #FCF8F1로 따로 정해져 있어 다른 화면(#FEFEFD)과 달랐다. 벽색을 #FEFEFD로 바꾸고 빛 보정(`light-calibration.generated.ts`)을 다시 만들었다(UPDATE_CALIBRATION=1). 보정은 빈 줄 벽 가운데가 새 벽색이 되도록 노출(gain 1.70 → 1.85)과 벽·판·종이 반사율을 다시 맞춘다 — 판 #F2DCC1·책 색은 그대로 나온다.
에뮬레이터 실측(`25-home-wall.jpg`: 전 · 후 · 설정): 머리글 쪽 벽 #FDFBF6 → #FEFEFE, 탭 바 자리 #F9F3E8 → #FDFDFB, 판 앞면 #F2DCC1 → #F2DCC0. 판·책 그림자는 빛 계산 그대로 옅은 회갈색.
