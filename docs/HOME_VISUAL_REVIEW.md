# 홈 화면 시안 대조 및 수정 (2026-09-27)

## 차이가 생긴 원인

1. 예시 자산에서 제목을 지우고 다시 조판하면서 일부 배경 그림과 종이 결이 손상됐다. 그림을 여러 띠로 나눠 세로로 늘리는 처리까지 겹쳐 원본의 구도와 비율이 달라졌다.
2. 원본에 이미 포함된 책 윗면 위에 코드 윗면을 덧그렸다. 특히 눕힌 책에서 종이 띠가 중복되어 책이 갈라진 것처럼 보였다.
3. 책갈피의 작은 View 밖으로 반복 종이 텍스처가 넘쳤다. 책 뒤에 사각형 회색 얼룩처럼 보이던 부분의 원인이었다.
4. 기존 저장 배치에 빈 네 번째 선반이 남아 있었다. 1차 수정의 가변 줄 간격도 이후 요청한 균등 간격과 맞지 않았다.
5. 추가된 헤더 버튼, 진한 배경 질감, 두꺼운 선반과 그림자가 목표 이미지와 다른 인상을 만들었다.
6. 2차 수정의 선반 그림자는 가까운 부분의 농도에 비해 먼 부분이 빠르게 사라졌다. 책의 접촉선도 윗면 뒤쪽에서 70% 지점에 있어 앞턱까지 남는 나무 면이 약 4DU뿐이었다.

## 적용한 변경

- 사용자가 제공한 목표 이미지 원본을 변경 없이 번들에 보관하고, 예시 18권의 윤곽을 개별 SVG로 표시한다. 기본 자세에서는 원본 색·질감·그림 비율·글자를 유지한다.
- 기울어진 원본 책은 역회전 좌표로 정의하고 앱의 실제 기울기를 적용한다. 같은 윤곽을 터치 판정과 그림자에 사용하며 실제 밑면이 선반 바닥에 닿게 보정한다.
- 선반을 3개로 고정하고 같은 간격으로 배치한다. 선반 묶음은 헤더와 하단 아이콘 사이의 중앙에 놓는다. 기존 초과 선반의 책은 서랍으로 보존한다.
- 책을 실제 윤곽의 높이별 단면으로 밀착 배치한다. 사각형 점유 폭 때문에 생기던 기울인 책 옆의 큰 틈을 없앴다. ‘흰’의 원본 아래쪽 배경 여백을 걷어내고 접촉 그림자를 강화했다. 이미지 경계의 벽색은 소폭 안쪽 샘플링으로 제외한다.
- 선반의 좌우 여백은 2DU, 두께 배율은 0.94다. 책·선반 그림자는 Skia 블러로 그리며 접촉층과 넓은 확산층을 강화했다. SVG의 제한된 블러 폭으로 생기던 얇은 띠 모양을 대체했다.
- 하단 라벨을 제거하고 책장·기록·마이를 모두 채워진 아이콘으로 표시한다. 투명한 하단 내비게이션을 장면 위에 겹쳐 그림자가 하단 경계에서 끊기지 않는다. 접근성 이름은 유지한다.
- 배경을 따뜻한 크림색으로 조정하고 종이 텍스처 불투명도를 낮췄다. 헤더는 가벼운 명조 제목과 하나의 + 버튼으로 정리했다. 꾸미기·서랍은 + 메뉴로 접근한다.
- 선반 그림자의 긴 층을 82DU로 늘리고 거리별 불투명도를 연속 보간한다. 50DU 이후에도 옅은 그림자가 이어지며, 마지막 흐림까지 그릴 수 있도록 캔버스 여백도 확보한다. 책의 확산 그림자도 오른쪽 27/39DU, 아래 24/35DU로 늘렸다.
- 책 접촉선을 선반 윗면 뒤쪽에서 28% 지점으로 옮겨 책 앞에 약 9.6DU의 나무 면을 남긴다. 벽 그림자는 선반 이미지 뒤, 접촉 그림자는 윗면 위에 그린다. 앞턱은 책보다 앞에 그려 깊이 순서를 지킨다.

## 검증

- TypeScript 검사 통과.
- Jest 6개 스위트, 69개 테스트 통과. 배치·쌓기·이동, 책 윤곽 충돌/밀착과 바닥 접촉, 선반 간격/중앙 정렬, 초과 선반 도서 보존, 280/390/520/768px 화면의 터치 좌표 복원을 검증했다. 예시 이미지가 없는 신규 도서도 책등 -7/0/+7도·앞표지·가로 쌓기에서 바닥 접촉과 점유 폭을 확인했다. 이 검증은 생성 이미지의 미적 품질을 보장하지 않는다.
- Android 에뮬레이터의 Expo Go에서 홈 화면 및 책 선택 팝오버를 캡처해 육안 검토했다. + 메뉴에서 서랍 열기와 제자리 드래그 후 복귀도 확인했다.
- 최신 수정 화면: [홈 캡처](screenshots/13-home-shadow-depth.png). 회색 톱니는 Expo Go의 개발 메뉴이며 앱 화면 요소가 아니다.
- 첫 3개 선반의 책 순서와 저장된 기울기는 유지한다.

## 남은 제약

- 예시 기본 자세의 제목은 그림에 포함되어 있다. 이 방법은 목표 분위기를 확인하기 위한 샘플 렌더링이다. 실제 도서의 생성 자산·제목은 기존 URI/조판 경로를 사용한다.
- 사진 등록 → Gemini 재장정 생성 → 저장 → 홈 배치 흐름은 아직 연결되지 않았다. 이번 변경은 홈 렌더링과 예시 품질 개선이다.
- 목표 이미지는 941×1672이며 시스템 상태 표시줄이 없다. 더 긴 휴대폰 화면은 상태 표시줄·안전 영역·하단 여유 공간 때문에 전체 화면의 비율이 같을 수 없다. 책 자체의 비율은 유지한다.
- iOS와 실제 기기에서의 표현, 많은 책을 관리할 때의 성능은 별도 검증이 필요하다.

## 생성 이미지 연결 시 지킬 규격

생성 이미지에는 다른 책·선반·벽·바깥 그림자가 섞이지 않도록 하고 책별 앞표지/책등 아트를 저장한다. 제목과 바깥 그림자는 앱에서 표시한다. 원본 비율을 유지하고 이미 그려진 윗면·옆면에 코드 면을 중복해서 추가하지 않는다. 목표 분위기는 샘플만으로 보장되지 않으므로 생성 결과도 같은 화면에서 대조해야 한다.
