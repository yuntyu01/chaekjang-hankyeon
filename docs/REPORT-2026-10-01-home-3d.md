## 홈 3D 구조 정리 - 단계별 결과 (2026-10-01)

진단과 변경 전 기준은 [REPORT-2026-10-01-home-3d-diagnosis.md](REPORT-2026-10-01-home-3d-diagnosis.md)에 있습니다.
확인 방법 표기: **테스트** = jest 자동 테스트, **에뮬** = 에뮬레이터(측정 번들 릴리스 빌드)에서 직접 조작·캡처·녹화, **실기기** = 이번에는 확인하지 못했습니다.

### 1단계: 좌표·상태·터치 일치

#### 구조
- 카메라는 하나입니다(`domain/camera.ts`). 보기 각은 화면 카메라(UI 스레드 값)만 바꾸고, 배치·충돌·줄 간격은 카메라를 읽지 않습니다. 전역 카메라를 고치던 `setViewPitch`, 옛 2D 바닥값 178, 줄마다 카메라(`VIEW_BY_POSITION`)를 없앴습니다.
- 줄 간격은 3D 값입니다(가장 큰 책 + 갈피 + 여유, 모든 줄 같음). 3° 기본 보기에서 예전 줄 위치와 같고, 꾸미기·저장된 보기 각이 줄 높이를 바꾸지 않습니다(`rowShift`·`pendingScroll` 보정 제거).
- 장면 상태: 줄마다 움직임(트랙 + 진행률)과 줄 위치, 공통 카메라가 UI 스레드에 있고, 책 면·그림자·선택 빛·손잡이·터치 판정이 같은 프레임의 3D 자세를 읽습니다(`ui/shelf/scene.ts`).
- 경로 계획(`ui/shelf/planner.ts`): 지금 보이는 자세에서 새 배치로 가는 경로를 짜고, 여러 줄을 한 번에 UI로 보냅니다. 경로 검사가 시간 안에 안 끝나거나 모두 막히면 앞으로 빼서 옮기는 대체 경로를 씁니다(순간 이동·'자리 없음' 거절 없음).
- 캔버스: 줄마다 하나 + 맨 위 이동 캔버스 하나(아래 '캔버스 구성').

#### 고친 문제
| 문제 | 고친 방식 | 확인 |
|---|---|---|
| 책 왼쪽 띠·겹친 책을 누르면 옆·뒤 책이 잡힘 | 터치를 UI 스레드에서 지금 자세·카메라·가림 순서로 판정(가장 앞에 보이는 책, 윗선반 판이 앞이면 책 아님) | 에뮬(데미안 왼쪽 끝 → 데미안), 테스트(앞뒤 겹침·쌓인 책·윗선반 판) |
| 누운 더미 앞 표지 책을 잡자마자 쌓임 | 끌기 목표 계산이 자기 자리를 먼저 봄 | 테스트 |
| 선택하면 책이 7DU 뜸 | 들림 없앰, 윤곽 빛만(꾸미기 밖에서도) | 에뮬 |
| 끌기 중 줄 ↔ 따로 뜬 그림 전환 때 튐·중복·빈 프레임 | 따로 뜬 그림(드래그 오버레이) 없앰: 놓을 수 있으면 그 자리에 보이고, 없으면 제자리 + 안내 | 에뮬 녹화 |
| 다른 줄로 옮길 때 중복·빈 프레임·순간 이동 | 옮겨 갈 만한 책을 이동 캔버스에 미리 올리고, 원래 줄이 빠지기 전에 넘겨받고, 도착 줄 캔버스에 올라간 뒤 경로를 시작 | 에뮬 녹화(보통 속도·느린 재생 ×8) |
| 경로 없음 → 순간 이동, 가능한 자세 바꾸기를 '자리 없음'으로 거절 | 시간 예산 + 검증된 대체 경로(위에 얹힌 책 먼저, 막는 책은 잠깐 빼 두기) | 테스트 |
| 손잡이·막대를 놓았는데 미리보기 자세가 남음 | 놓을 때 확정 또는 되돌린 배치로 맞춤, 막대 취소도 같게 | 코드·에뮬 |
| 앞뒤 막대가 표지 책의 벽 기대기 상태를 옛 필드로 읽음 | 기울기(pitch)로 읽음 | 코드 |
| 아래 줄을 끌면 조작부가 그 줄을 덮음 | 끄는 동안 조작부 숨김 | 에뮬 |

#### 8° 가림 확인
- 예시 배치는 8°에서도 둘째·셋째 줄 책머리가 윗선반 판 아래에 여유가 있어 겹치지 않습니다.
- 표지 책을 앞뒤 막대로 벽 쪽 끝(179mm)까지 밀면 머리 윗부분이 윗선반 판 앞면 뒤로 들어가 가려집니다. 형상 보기의 책 상자 윗변이 판 아래 모서리보다 위에 있어 실제 3D 가림이고, 헤더나 캔버스 경계에서 잘린 것이 아닙니다(`screenshots/83-stage1-plank-occlusion.png`).
- 보이는 부분을 누르면 그 책이 선택되고, 표지 책 손잡이는 판 위에 떠 있어 잡을 수 있습니다. 가림을 없애려고 줄 간격을 늘리지 않았습니다.
- 3° 기본, 꾸미기 3°, 꾸미기 8°, 8° 형상 보기에서 줄 위치가 같습니다(`screenshots/82-stage1-rows-fixed.png`).

#### 캔버스 구성 선택
가림을 정확히 표현하는 두 구성을 같은 장면 상태 위에 두고, 같은 빌드에서 딥링크로 바꿔 번갈아 3회씩 쟀습니다(에뮬, UI 프레임 간격 평균 ms).

| 구성 | 시점 3°→8°→3° 두 번 | 끌기(같은 줄 + 다른 줄 시도) |
|---|---|---|
| 캔버스 하나(장면 전체 가림 순서) | 245.8 / 231.2 / 226.5 | 169.7 / 94.6 / 119.8 |
| 줄마다 캔버스(윗선반 판 윤곽으로 자름) | 375.8* / 256.7 / 220.6 | 74.4 / 59.7 / 55.8 |

*첫 회는 투영 계산만 잰 값도 2배라 에뮬 전체가 느렸던 회입니다. 시점 전환은 비슷하고 끌기는 줄마다 캔버스가 약 2배 빨라(끄는 줄만 다시 그림) 이쪽을 골랐습니다. 줄마다 캔버스에서 줄을 넘는 가림은 이렇게 맞춥니다.
- 아래 줄 캔버스가 위에 겹치고, 한 줄의 모든 그림을 윗선반 판의 투영 윤곽 밖에만 그립니다(줄 공간 안의 것은 모두 윗선반 판보다 뒤).
- 다른 줄로 옮겨 가는 책(제 줄 공간 밖에 걸친 동안)은 맨 위 이동 캔버스가 그리고, 모든 줄의 책·판 가운데 그 책 앞에 있는 것의 윤곽 밖에만 그립니다(`screenshots/84-stage1-cross-row-slow.png`, 빨간 선 = 앞에 있어 자르는 윤곽).

#### 성능(변경 전 APK ↔ 1단계, 같은 세션에서 번갈아 3회, 에뮬)

- 끌기는 좋아졌고 시점 전환은 비슷합니다. 첫 화면·조작 가능 시각은 회마다 편차가 커 차이를 말하기 어렵습니다(마지막 단계 뒤 다시 잽니다).

### 2단계: 책 구조

#### 구조
- 책 몸체를 책 좌표의 조각으로 정했습니다(`domain/book-parts.ts`): 판 두 장(두께 = 책 두께 × 0.08, 1.1~1.8DU), 머리·꼬리의 책등 띠, 그 사이 속지 묶음. 판은 속지보다 머리·꼬리·책배 쪽으로 1.6DU 나와 있어(판 끝 여유) 속지 면은 판 끝보다 그만큼 안쪽 평면에 있습니다.
- 머리·꼬리·책배 면은 '판 사이 칸(그늘진 종이) → 들어간 속지 면 → 카메라 쪽을 향한 판 안쪽 벽 → 판·책등 테두리' 순서로 그립니다(`ui/book3d/BookFaces.tsx`). 들어간 속지 가운데 앞 면 뒤로 숨는 부분은 앞 면이 나중에 덮으므로, 얼마나 보이는지를 자세와 카메라가 정합니다(3°에서는 책등에서 약 30DU 깊이까지 숨고, 8°에서는 약 11DU).
- 둥근 모서리는 책 전체 투영 윤곽을 공통 반지름(2.2DU)으로 깎는 자르기 하나입니다. 모든 면·받는 그림자·빛이 같이 잘리고, 그리는 모양은 충돌 상자 밖으로 나가지 않습니다(테스트). 갈피 끈만 윤곽 밖에 그립니다.
- 속지 면(종이색·결·판 쪽 그늘)은 책마다 한 번 그림으로 기록해 두고 매 프레임 면 변환 행렬만 바꿉니다. 책등·앞표지 그림도 면 전체 사각형으로 기록합니다.

#### 없앤 것
- 옆면을 화면 px로 만들던 둥근 모서리·손그림 흔들림·볼록한 머리, 앞면 모서리 틈을 가리려고 옆면을 2.4DU 밀어 넣던 보정(`softFace`, `under`, `BOX_HEAD_BOW`).
- 책등·표지 그림에 구워 넣은 둥근 윤곽·흔들림·어두운 가장자리 선(`spineOutline`, `coverOutline`, `EdgeLine`, `Joined`), 매 프레임 계산하던 속지 구조 선·그늘 경로, `FaceShape.tsx`.

#### 확인
- 테스트: 판이 두께 방향 양끝·속지가 판 끝보다 안쪽, 3°/8°에서 숨는 깊이(sq/ky), 보이는 안쪽 벽, 눕힌 책 끝면, 윤곽이 투영 상자 안·판 아래로 내려가지 않음.
- 에뮬: 3°·8° 같은 배치 캡처(`screenshots/85-stage2-book-structure.png`). 처음에는 판 안쪽 벽과 칸을 판 색을 낮춘 색으로 칠해 표지 책 머리가 갈색 줄처럼 보였고, 면지(종이)색 그늘로 고쳤습니다(맨 아래 확대).

#### 성능(1단계 ↔ 2단계, 같은 세션 번갈아 2회, 에뮬)
| 항목 | 1단계 | 2단계 |
|---|---|---|
| 시점 전환 프레임 평균(ms) | 306.4 / 272.2 | 166.7 / 159.7 |
| 면 투영 계산만(18권, 프레임당 ms) | 24.0 / 18.1 | 2.5 / 2.8 |
| 다른 줄로 끌기(ms, p90) | 42.5 / 59.4 (p90 100~167) | 39.1 / 35.2 (p90 83) |

- 옆면을 매 프레임 화면 좌표로 계산하던 비용이 컸습니다. 여섯 면 준비 방식은 측정대로 '그림이 붙는 면은 한 번 기록 + 면 변환 행렬, 단색 테두리·벽은 꼭짓점 몇 개의 다각형'으로 정했습니다.

### 3단계: 그림자와 움직임 연동

#### 바꾼 것
- 광원·그림자 값을 `ui/lighting.ts` 하나로 옮겼습니다(값 그대로, theme.ts는 다른 세션 파일이라 고치지 않음).
- 책 면이 받는 그림자: 3D 단계를 순수 모듈(`domain/received3.ts`)로 옮겼습니다.
  - 가리개 칸을 3개로 늘리고 윗선반 판을 늘 첫 칸에 둡니다(예전: 두 칸, 가까운 책 둘이 있으면 판 그림자가 먼저 빠짐).
  - 그라데이션 축을 가리개의 가까운 가장자리에 수직으로 잡습니다(예전: 판 끝 한 점을 기준으로 잡아 선반 왼쪽 책이 더 어둡고 키 큰 책에 가로 띠가 생김).
  - 그 책에 그림자를 드리울 수 있는 범위(왼쪽 90DU, 오른쪽 12DU)의 책만 가리개로 보고, 그 책들의 자세가 바뀔 때만 다시 계산합니다. 옮긴 책과 그 그림자를 받는 이웃은 같은 프레임에 같이 바뀌고, 나머지 책은 끄는 동안 계산하지 않습니다.
- 선반 윗면 그림자: 책을 들어 올리는 순간 통째로 사라지던 것을 높이에 따라 옅어지게(14DU까지) 했습니다. 빛 방향으로 밀려 흐려지는 것은 기존 투영이 합니다.
- 기대기 접촉 어둠: 받치는 책에 실제로 닿아 있을 때만 그립니다(예전: 1~45° 기울면 받침과 상관없이).
- 선반 판 명암: 고정 틴트·고정 흰 모서리 선 대신 책과 같은 공통 광원 램버트와 모서리 규칙(두 면 사이 법선이 빛을 더 받는 만큼만 밝게).
- 움직임: 같은 판형 책은 어긋남 없이 맞춰 쌓습니다(예전: 8DU 어긋나 받침 밖 → 쌓기 불가, 예시 18권 중 7권이 같은 판형). 배치에 없는 책(추가하고 자리를 고르지 않은 책)이 있으면 확정할 때 서랍에 넣어 이후 확정이 막히지 않게 했습니다.

#### 확인
- 테스트: 판 + 가까운 책 둘이 한 면에 모두 남음, 판 그림자 그라데이션이 받는 책 위치와 무관(세로), 같은 판형 쌓기(위 책 가로 자리 = 아래 책), 기존 받는 그림자 이동 테스트.
- 에뮬: 8° 둘째 줄 책머리 아래 판 그림자, 아몬드를 앞뒤 막대로 앞으로 뺄 때 오른쪽 달러구트가 같은 순간 새 자리에 다시 기댐.
- 처음 구현(결과를 같은 계산 안에 저장)은 움직이는 책이 있으면 계산이 자기 자신을 계속 불러 끌기가 3배 느려졌습니다(같은 줄 40 → 119~127ms). 자세 서명이 바뀔 때만 계산하는 반응으로 나눠 되돌렸습니다(53.7ms, 다른 줄 34.9ms).

### 4단계: 재질

#### 바꾼 것(모두 공통 규칙, 광원·자세를 따라 바뀜)
- 둥근 모서리: 반지름 2.2 → 3.0DU. 책 전체 투영 윤곽을 깎는 자르기 하나라 모든 면·받는 그림자·빛이 같이 깎이고, 그리는 모양은 충돌 상자 밖으로 나가지 않습니다(테스트 그대로 통과).
- 제본 홈: 앞표지 그림과 판 면(뒤표지·비스듬히 옆으로 간 앞표지)이 규칙 하나(`GROOVE`)를 씁니다. 책등 쪽 변에서 5DU 안쪽에 책 색을 낮춘 좁은 그늘, 바로 뒤에 책 색을 밝힌 가는 밝음. 예전에는 앞표지 그림은 폭의 4% 자리에 고정 흑갈색 선과 흰 선, 판 면은 다른 자리·색이었습니다.
- 선반 윗면 접촉 어둠: 화면 좌표의 띠 대신 선반 윗면 위 3D 층 세 겹(책 바닥 앞 모서리에서 2.5·9·24DU, 진하기 0.14·0.09·0.05). 같은 3D 모양을 투영만 바꿔 3°에서는 얇고 8°에서는 넓게 보입니다.
- 책 → 벽·선반 윗면 그림자를 한 모델로(`domain/cast-shadow.ts` `bookCast`, 값은 `lighting.ts` `shadow.cast.book`).
  - 예전: 벽은 책마다 '가장 가까운 면부터 잰' 층(0.06·0.07·0.09, 따뜻한 갈색), 선반 윗면은 바닥부터 잰 층(0.1씩, 짙은 회갈색)이라 두 면이 만나는 선에서 같은 빛줄기가 벽 0.204, 선반 0.100으로 끊겼습니다(진단 항목).
  - 지금: 두 면 모두 빛 길이(가리는 점 → 받는 점)의 같은 절대 문턱(20·70DU·끝까지)·같은 진하기(0.08·0.1·0.1)·같은 색. 이음선 한 점으로 가는 빛줄기는 두 면까지의 빛 길이가 같아서 진하기가 그대로 이어집니다. 책의 가장 가까운 점이 문턱을 넘나들 때는 그 층을 빛 길이 6DU에 걸쳐 옅게 해, 앞뒤로 옮기는 동안 층이 한 번에 나타나지 않습니다.
  - 결과(흐림 제외 계산): 이음선 최대 차 0.104 → 0(책 깊이 4가지). 책 뒤 벽 그림자는 거리와 상관없이 0.204였던 것이 벽과의 거리에 따라 0.10(앞으로 뺀 책)·0.19(기준 자리)·0.26(벽 가까이)으로, 선반 윗면 발치는 0.271 → 0.255.
- 2~3단계에서 공통 광원으로 바꿔 둔 책등 곡면(원통 명암)·빛 받는 모서리(베벨)·판 명암(램버트)·밝은 속지 면은 그대로 두고 3°·8°에서 다시 확인했습니다. 쓰이지 않게 된 옛 구운 명암·외곽선 도우미(`spineProfile`, `edgeFactor`, `GrainFill`)와 중복 모서리 목록을 지웠습니다.

#### 정리한 구조

#### 남은 문제
- 이 에뮬레이터에서 다른 줄로 옮기는 동안 UI 프레임 간격이 약 200ms라 560ms 경로가 3~4프레임으로 보이고, 도착 줄 캔버스를 다시 기록하는 0.6~1초 동안 책이 제자리에서 기다립니다. 느린 재생에서 중복·빈 프레임은 없었고, 실기기에서의 체감은 확인하지 못했습니다.
- 책 면이 받는 그림자(`onBook`·`onBookPlank`)는 아직 따로의 감쇠(가장 가까운 빛 길이 기준)와 색을 씁니다. 앞으로 뺀 책이 이웃 책등과 그 앞 선반 윗면에 함께 드리우는 경우 두 면의 진하기가 이어진다고 보장하지 않습니다. 색도 받는 곳마다 다릅니다(책 그림자 `#7A5236`, 판 그림자 `#864C21`, 책 면이 받는 그림자와 접촉 어둠 `#3B3330`). 이번에 같아진 것은 책 그림자의 벽·선반 윗면 두 면입니다.
- 판 앞면 바로 아래 좁은 어둠(`shelfLip`)은 3D 모서리에서 시작하지만 폭이 화면 px 고정인 분위기 층입니다.
- 넓은 표지 책 한가운데에 놓으면(그 책을 통째로 한쪽으로 옮길 공간이 없으면) 규칙대로 '자리 없음'입니다.
- 아래 줄 책을 끌어 놓으면 꾸미기 패널이 그 줄을 덮은 채로 남습니다(끄는 동안은 숨기고, 표지 책을 탭으로 고르면 보이게 스크롤됨).
- 윗손잡이는 끈 거리에 비례해 각도가 바뀌어 손가락을 그대로 따라오지 않고, 돌리기 막대는 누른 자리의 각도로 바로 갑니다.
- 저장 후 다시 실행: 측정용 예시 책장은 저장하지 않는 메모리 전용이라 에뮬레이터에서 같은 배치로는 확인할 수 없어, 확정 → 저장소 → 다시 불러오기 왕복 테스트로 확인했습니다(SQLite 엔진 자체는 모의 저장소로 대신). 실제 데이터로 기기에서 다시 여는 확인은 남아 있습니다.
- 응답 없음(ANR): 진단에서 찾은 홈 화면 쪽 후보 두 가지(경로 탐색 실패 때 JS 2~3초 멈춤, 끄는 중이 아니어도 매 프레임 돌던 자동 스크롤 콜백)는 없앴습니다. 홈 밖 화면(서랍·검색·통계·장정 고르기)의 정적 썸네일이 권마다 캔버스와 전체 애니메이션 경로를 돌리는 것과 메모리 압박은 손대지 않았고, 원인은 실기기 트레이스로 확인해야 합니다. 에뮬레이터 탓으로 확정하지 않았습니다.
